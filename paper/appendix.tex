\subsection{Reproduction sequence}
From the project root, use Python 3.12 and a TeX installation providing pdfLaTeX, BibTeX, \texttt{latexmk}, Latin Modern, TikZ, natbib, and IEEEtran. The pinned Python requirements accompany the scripts. The following sequence rebuilds the analysis and manuscript:
\begin{lstlisting}[basicstyle=\ttfamily\footnotesize]
python3.12 -m venv .venv
.venv/bin/python -m pip install -r analysis/requirements.txt \
  -r analysis/requirements-metrics.txt
.venv/bin/python analysis/run_analysis.py
.venv/bin/python analysis/recompute_metrics.py
.venv/bin/python analysis/validate_workflows.py --refresh
.venv/bin/python analysis/audit_workflow_robustness.py
.venv/bin/python analysis/build_paper_assets.py
make -C paper
.venv/bin/python analysis/package_release.py
.venv/bin/python analysis/verify_release.py
\end{lstlisting}
The workflow script obtains actionlint 1.7.7 from its official release and verifies the archive checksum; \texttt{--refresh} repeats checks rather than reusing the content cache. Poppler and Pillow support the final rendering comparison. The verifier freshly extracts and compiles the Overleaf archive, renders both PDFs, and compares their pages. Its output, \path{output/verification.json}, is a separate release record beside the two ZIP archives; it is not embedded in the reproducibility ZIP.

The manuscript's tables and worked listings are generated from the exported results or raw input fields by \path{analysis/build_paper_assets.py}. The workflow sensitivity table is generated by the dedicated audit script. Original input files are checked against their recorded SHA-256 hashes. This preserves the distinction between a changed analysis and changed source data.

\subsection{Units, statuses, and selection records}
The \texttt{ID} column joins documentation, archived outputs, scores, and diagnostics. A model--reference row identifies one example and one model; a policy row identifies one example and one selector. Lexical summaries retain all 1,318 examples. Structural summaries use the fixed 1,293 eligible references: a failed generated parse receives zero, while an ineligible reference receives an unavailable value. These cases must not be combined into a smaller, implicitly conditional denominator.

Workflow records use the separately declared 335-example shape restriction. Acceptance, rejection, and abstention remain distinct: rejection is a checker outcome for a candidate, while abstention means that no candidate in the supplied priority list passed. The reusable interface in \mbox{\path{analysis/select_configuration.py}} records the attempted candidates and their diagnostics. It returns the selected text with exit status zero, or status 2 when all candidates fail. The CLI applies syntax or workflow checking according to the declared scope; the structural consensus experiment is implemented separately in the metric script.
